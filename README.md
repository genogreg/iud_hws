# iud_hws

Учебный проект по анализу датасета METABRIC: клинические и генетические
признаки пациенток с раком молочной железы. В проекте есть ETL-пакет,
который готовит данные и записывает их в PostgreSQL, и ноутбук с
исследовательским анализом.

## Датасет

Источник: [Google Drive](https://drive.google.com/file/d/1MOB-lzitxMdv-mju9oAUgy0LdmoAX4ql/view?usp=share_link)

- Пациентов (строк): 1 904
- Признаков (столбцов): 693
- Клинические признаки: 31
- Столбцы экспрессии мРНК: 489
- Столбцы мутаций (`*_mut`): 173

В данных есть числовые, категориальные и логические признаки, а также
пропущенные значения.

## Пакет etl

Пакет выполняет полный цикл подготовки данных. Шаги запускаются по порядку
из `main.py`. Ссылка на датасет, пути к файлам и ограничение в 100 строк
лежат в `config.py`. Пути считаются от корня проекта, поэтому ETL можно
запускать из любой папки.

| Шаг | Файл | Что делает |
|---|---|---|
| Extract | `extract.py` | Скачивает CSV с Google Drive в `data/`, если его там ещё нет, и читает в DataFrame. Файл сначала качается во временный `.part` и переименовывается только после успешной загрузки, поэтому оборванная загрузка не оставит битый CSV |
| Transform | `transform.py` | Приводит типы: `patient_id` → строка, признаки терапии и выживаемости → `boolean`, когорта, степень злокачественности, число лимфоузлов, число мутаций и стадия → `Int64`, столбцы `*_mut` → `boolean` (есть мутация или нет), остальные текстовые → `category` |
| Validate | `validate.py` | Проверяет обязательные столбцы, уникальность и заполненность `patient_id` и допустимые диапазоны: возраст 0–120, размер опухоли больше 0, стадия 0–4, лимфоузлы и длительность наблюдения не меньше 0. При ошибке пайплайн останавливается до записи |
| Load | `load.py` | Сохраняет весь обработанный датасет в `data/METABRIC_RNA_Mutation.parquet` и записывает первые строки (не больше 100) в таблицу PostgreSQL |

Аргументы `main.py`:

| Аргумент | По умолчанию | Описание |
|---|---|---|
| `--table` | `travingk` | имя таблицы в БД: строчные латинские буквы, цифры и `_` |
| `--rows` | `100` | сколько строк записать в БД, от 1 до 100 |

Аргументы проверяются до запуска пайплайна. Имя таблицы ограничено этими
символами, потому что оно подставляется в SQL-запрос проверки.

Если таблица уже существует, она перезаписывается, поэтому при повторном
запуске в ней остаётся ровно столько строк, сколько указано в `--rows`.

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -e .
```

`pip install -e .` ставит пакет `etl` и библиотеки, нужные для ETL:

- `gdown` — скачивание датасета с Google Drive;
- `pandas`, `pyarrow` — обработка данных и сохранение в Parquet;
- `sqlalchemy`, `psycopg2-binary` — подключение к PostgreSQL;
- `python-dotenv` — чтение настроек подключения из `.env`.

Служебные библиотеки для ноутбука и скриптов лежат в группе `dev`
(`jupyter`, `matplotlib`, `seaborn`, `plotly`, `kaleido`, `requests`):

```bash
pip install -e . --group dev
```

Опция `--group` есть в pip начиная с версии 25.1, поэтому при установке
pip сначала обновляется.

## Настройка подключения к БД

Данные для подключения хранятся только в файле `.env`, который добавлен в
`.gitignore`. Файл `creds.db` в репозиторий тоже не попадает: все `*.db`
файлы в `.gitignore`.

Доступы выдаются в виде SQLite-базы `creds.db` с таблицей `access`.
Скрипт `scripts/read_creds.py` открывает её через `sqlite3`, выбирает
доступ к нужной БД и записывает его в `.env`. Сами доступы на экран не
выводятся.

```bash
python scripts/read_creds.py путь/к/creds.db
python scripts/read_creds.py путь/к/creds.db --db freezone
```

По умолчанию берётся доступ к БД `homeworks`.

Можно заполнить `.env` и вручную по шаблону `.env.example`:

```bash
cp .env.example .env
```

В `.env` должны быть `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER` и
`DB_PASSWORD`.

## Запуск

```bash
python -m etl.main
python -m etl.main --table travingk --rows 50
python -m etl.main --help
```

Пример вывода:

```
Extract: 1904 строк, 693 столбцов
Transform: типы данных приведены
Validate: проверки пройдены
Load: полный датасет сохранён в data/METABRIC_RNA_Mutation.parquet
Load: в таблицу travingk записано 100 строк
```

## Ноутбук

`notebooks/EDA.ipynb` читает `data/METABRIC_RNA_Mutation.parquet`, поэтому
сначала нужно запустить ETL. В ноутбуке есть структура и качество данных,
пропуски, выбросы, распределения, частоты мутаций, корреляции и графики
Plotly.

```bash
jupyter lab notebooks/EDA.ipynb
```

## Отдельные скрипты

- `scripts/read_api.py` — собирает 100 последних сообщений о нежелательных
  реакциях на лекарства из openFDA API и сохраняет их в
  `data/openfda_events.parquet`. Подробнее в `scripts/README.md`.
- `scripts/read_creds.py` — читает доступы из `creds.db` и создаёт `.env`.
- `scripts/write_to_db.py` — записывает первые 100 строк готового Parquet в
  таблицу `travingk`, а затем читает её обратно для проверки.
